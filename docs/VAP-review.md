# VAP 卡顿排查与修复

日期：2026-10-29。范围：MotionScope 的 VAP 接入、上游 `video-animation-player@1.0.5`、工作台视频生命周期与定位队列。

## 发现与修复

| 优先级 | 问题与依据 | 处理 |
| --- | --- | --- |
| P1 | 上游 `requestAnimFunc()` 用 `index % (60 / fps)` 判断渲染。24 FPS 的间隔为 2.5，只有部分整数 index 满足；25 / 29.97 FPS 还受浮点取模影响。90 / 120 Hz 也不符合固定 60 Hz 假设。 | 禁用上游定时循环，优先跟随 `requestVideoFrameCallback`，降级时按实际媒体时间去重，不按显示器刷新次数取模。 |
| P1 | 上游 `pause()` 只暂停 video，绘制链仍会继续 `texImage2D`。原接入的 seek / snapshot 调用上游 `drawFrame()`，该函数还会继续安排下一帧。 | 单独管理一个可取消的渲染链；暂停时取消；seek 和 snapshot 仅绘制一次。回调带代次校验，避免已取消的旧回调再次启动循环。 |
| P1 | 快速拖动时间线时，原工作台每次输入都会建立等待 busy 的任务，并可能多次操作同一解码器。 | 主工作台和视频适配器均使用“正在执行 + 最新待执行”队列，丢弃中间目标，不并发定位。 |
| P1 | 原视频循环和工作台循环都可能在末尾 seek；异步异常可跳过下一次工作台 RAF。 | 完整原生循环交给 video；A–B 和单次播放由工作台控制；解码暂未就绪时等待而非立即报错；RAF 在 finally 中安排，旧操作由代次校验隔离。 |
| P2 | 上游 destroy 移除视频元素，但没有明确 pause / 清空 src；资源替换及文件切换还可能与旧 seek 交错。 | 取消驱动与事件、abort 等待中的 seek、暂停并卸载解码源、销毁 GL 资源；替换操作占用工作台互斥状态。 |
| P2 | 上游每帧查找 frame 数据并创建坐标数组；没有融合对象的帧不会清空上一帧的 uniform。 | 预建帧索引，复用固定 Float32Array；每次清空融合区域再写入当前帧，防止头像 / 文字残留。 |

不直接修改 node_modules。`vap-renderer.js` 复用腾讯原有着色器和纹理初始化；`vap-draw.js` 执行单帧绘制；`video-frame-driver.js` 管理调度与队列。

## 验证

- 21 项 Node 测试通过，包含原有 11 项与新增 10 项回归。
- 调度模拟覆盖 20 / 24 / 25 / 29.97 / 30 / 60 FPS，配合 60 / 90 / 120 Hz；验证没有错误降帧或重复绘制。
- 回调取消、暂停后停止渲染、一次性截图、过期回调、销毁、异常停止、100 个连续定位请求合并为首个和最后一个，均有回归测试。
- GL mock 验证融合 uniform 会在对象减少或消失时清空。
- 使用官方 VAP 示例做真实浏览器对照：两个播放器暂停后，原播放器绘制计数由 107 增到 222，修复版保持在 104，`running:false`、`pending:false`。这是绘制次数对照，不是 CPU / GPU 占用百分比。
- 修复版暂停定位到 5 秒、截图、文字替换后仍停在 5 秒；两实例销毁后页面 video 元素数量为 0。
- 完整工作台验证倍速完整循环、关闭循环停在末帧及 A–B 区间循环。

复现页面：本地 `pnpm dev` 后打开 `/tests/vap-browser.html`。此测试页不进入生产构建。它对照原上游调度和新适配器，并将实际绘制次数显示到页面。

## 能力边界

本次修复调度、生命周期和接入层错误，未改变视频编码。高分辨率、高码率、不受设备支持的编码或过多融合纹理仍可能超过设备能力。真实视频的精确 seek 仍受关键帧和浏览器解码影响。新增检查报告的 `diagnostics` 字段记录调度模式、绘制计数、回调状态和异常，便于继续定位具体素材问题。
